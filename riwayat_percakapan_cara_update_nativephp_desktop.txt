RIWAYAT PERCAKAPAN: PERSISTENSI DATA & AUTO-UPDATE NATIVEPHP

================================================================================
TOPIK 1: Persistensi Data saat Build NativePHP
================================================================================
Pertanyaan: Apakah setiap build NativePHP desktop akan selalu mengosongkan storage dan reset database?

Jawaban:
Tidak, proses build atau update aplikasi pada NativePHP tidak akan selalu mengosongkan storage atau me-reset database milik pengguna. NativePHP dirancang layaknya aplikasi desktop modern. Berikut adalah mekanisme bagaimana data tetap aman dan bertahan (persistent) saat aplikasi diperbarui atau di-build ulang:

1. Penyimpanan Database (SQLite)
- Lokasi File: Saat aplikasi berjalan dalam mode production (setelah di-build), NativePHP secara otomatis membuat file 'nativephp.sqlite' di dalam direktori appdata sistem operasi pengguna (misalnya di folder AppData pada Windows atau Application Support pada macOS), bukan di dalam folder instalasi aplikasi itu sendiri.
- Mekanisme Update: Setiap kali pengguna membuka aplikasi versi terbaru, NativePHP akan mengecek apakah ada perubahan versi aplikasi. Jika ada perubahan, sistem hanya akan menjalankan perintah 'php artisan migrate' untuk memperbarui struktur tabel baru (jika ada file migration baru), tanpa menghapus atau merusak data lama yang sudah tersimpan di database pengguna.

2. Penyimpanan Storage (File & Settings)
- Sama seperti database, disk 'local' pada Laravel di lingkungan NativePHP dialihkan ke direktori appdata pengguna.
- Data yang disimpan melalui 'Storage::disk(...)' atau pengaturan yang disimpan melalui 'Settings::set()' akan tetap berada di sana dan tidak akan terhapus saat instalasi aplikasi ditimpa oleh versi yang lebih baru.

Kapan Data Bisa Terhapus atau Ter-reset?
Data di database atau storage hanya akan hilang jika terjadi kondisi berikut:
1. Proses Development vs Production: Di lingkungan development ('php artisan native:run'), NativePHP menggunakan database terpisah yang terletak di folder storage atau build proyek. Jika menghapus folder proyek atau menjalankan perintah 'php artisan native:migrate:fresh' secara manual, data development dipastikan hilang.
2. Perintah Seeder yang Salah: Jika menaruh perintah 'php artisan db:seed' di lifecycle boot aplikasi tanpa melakukan pengecekan apakah data sudah ada atau belum, data bisa saja tertimpa atau menjadi duplikat setiap kali aplikasi dinyalakan.
3. Pengguna Menghapus Folder AppData: Jika pengguna menghapus aplikasi secara total (clean uninstall) beserta folder data aplikasinya di sistem operasi, maka seluruh data storage dan database akan ikut terhapus.

Kesimpulan: Untuk perilisan ke pengguna akhir (production build), data user akan tetap aman dan persisten selama pembaharuan versi aplikasi. Cukup pastikan selalu membuat file migration baru untuk perubahan struktur database dan hindari penggunaan perintah 'migrate:fresh' di lingkungan production.

TOPIK 2: Pembaruan Versi (1.0.0 ke 1.1.0) dan Dampak Instalasi Menimpa Aplikasi
================================================================================
Pertanyaan: Misal saya sudah build production versi 1.0.0. kemudian saya ada update script di laravelnya dan saya update ke versi 1.1.0 dan saya build ulang aplikasinya.
1. Apakah pengguna yang sudah install versi 1.0.0 harus install ulang versi terbaru?
2. Bila install versi 1.1.0 dengan cara menimpa aplikasi yang lama, apakah database dan storagenya ke reset juga?

Jawaban:
1. Apakah pengguna harus install ulang versi terbaru?
Tidak selalu, tergantung pada metode pembaruan yang disediakan. NativePHP memiliki fitur Auto-Update bawaan (menggunakan Electron Updater).
- Jika Auto-Update Aktif: Pengguna tidak perlu mengunduh installer baru secara manual. Saat aplikasi versi 1.0.0 dibuka dan mendeteksi ada versi 1.1.0 di server pembaruan (misalnya via GitHub Releases), aplikasi akan mengunduh pembaruan di latar belakang dan meminta pengguna untuk me-restart aplikasi guna menerapkan versi baru.
- Jika Auto-Update Mati: Pengguna harus mengunduh file installer (.exe atau .dmg) versi 1.1.0 secara manual untuk memperbaruinya.

2. Jika diinstal dengan cara menimpa versi lama, apakah database dan storage akan ter-reset?
Tidak, database dan storage tidak akan ter-reset. Saat installer versi 1.1.0 dijalankan dan menimpa versi 1.0.0, berikut yang terjadi di komputer pengguna:
- File Kode Program Diperbarui: Hanya file eksekusi aplikasi dan skrip Laravel di dalam folder instalasi saja yang diganti ke versi baru.
- Database & Storage Aman: File database ('nativephp.sqlite') dan file storage tersimpan di folder khusus sistem operasi (folder AppData di Windows atau Application Support di macOS). Proses instalasi tidak menyentuh atau menghapus folder ini, sehingga semua data lama milik pengguna tetap utuh.
- Migrasi Otomatis: Saat aplikasi versi 1.1.0 pertama kali dijalankan setelah ditimpa, NativePHP akan otomatis menjalankan perintah 'php artisan migrate' di latar belakang. Jika menambahkan tabel atau kolom baru di versi 1.1.0, struktur tersebut akan langsung diterapkan tanpa menghapus data yang sudah ada.

TOPIK 3: Perubahan atau Penambahan Struktur Database saat Update
================================================================================
Pertanyaan: Misal yang berubah selain script ada juga database yang berubah atau bertambah..apakah akan ikut diupdate dengan yang terbaru? atau bagaimana?

Jawaban:
Ya, database pada komputer pengguna akan ikut diperbarui mengikuti struktur database terbaru yang dibuat di versi 1.1.0, tanpa menghapus data lama yang sudah mereka simpan. NativePHP memanfaatkan sistem Laravel Migrations untuk menangani perubahan ini secara otomatis.

Bagaimana Mekanisme Perubahannya?
Saat aplikasi versi 1.1.0 dijalankan pertama kali oleh pengguna, NativePHP akan memicu perintah 'php artisan migrate' di latar belakang.
- Jika ada tabel atau kolom baru: Laravel akan mendeteksi file migration baru yang belum pernah dijalankan pada komputer pengguna, lalu mengeksekusinya.
- Data lama aman: Karena proses ini menggunakan metode migration standar (bukan fresh atau rollback), data lama yang ada di tabel-tabel sebelumnya tidak akan hilang atau ter-reset.

Cara Mengubah Struktur Database yang Benar (Best Practices):
Agar database pengguna terupdate dengan aman, Anda harus mengikuti aturan migrasi Laravel:
1. JANGAN mengubah file migration lama: Jika sudah merilis versi 1.0.0, jangan pernah mengedit file migration yang sudah ada di folder 'database/migrations'.
2. SELALU buat file migration baru: Jika ingin menambah tabel, menambah kolom, atau mengubah tipe data, buatlah file migration baru menggunakan terminal.

Contoh Kasus (Menambahkan kolom 'phone_number' ke tabel 'users'):
1. Jalankan perintah di terminal proyek Laravel:
   php artisan make:migration add_phone_number_to_users_table
2. Isi file migration baru tersebut untuk menambahkan kolom:
   public function up(): void {
       Schema::table('users', function (Blueprint $table) {
           $table->string('phone_number')->nullable(); // Disarankan nullable agar data lama tidak error
       });
   }
3. Build aplikasi menjadi versi 1.1.0.

Ketika pengguna menginstal versi 1.1.0, NativePHP akan membaca file baru tersebut dan menambahkan kolom secara otomatis, sementara data lama tetap utuh.

TOPIK 4: Deteksi Perubahan Versi dan Logika di Balik Layar
================================================================================
Pertanyaan: Saya tertarik dengan mekanisme update dengan cara cek apakah ada perubahan versi aplikasi atau tidak. bagaimana cara implementasinya?

Jawaban:
Mekanisme pengecekan versi dan eksekusi migrasi saat aplikasi pertama kali dibuka ini sebenarnya sudah diatur secara otomatis oleh NativePHP di latar belakang. Anda tidak perlu menulis kode manual untuk mendeteksi perubahan versi atau menjalankan perintah 'migrate'.

1. Bagaimana NativePHP Mengetahuinya?
NativePHP memanfaatkan file konfigurasi 'config/nativephp.php'. Di dalam file tersebut, terdapat pengaturan versi aplikasi:
   'version' => env('NATIVEPHP_APP_VERSION', '1.0.0'),

Setiap kali Anda mengubah versi di file tersebut (misal dari 1.0.0 ke 1.1.0) dan melakukan build ulang, NativePHP akan menyimpan penanda versi baru ini ke dalam paket aplikasi. Saat pengguna membuka versi terbaru, bootstrapper NativePHP akan membandingkan versi aplikasi saat ini dengan versi yang tercatat di database lokal pengguna. Jika versinya lebih tinggi, perintah 'php artisan migrate --force' akan langsung dipicu secara otomatis.

2. Langkah-Langkah Implementasi Saat Update Aplikasi:
- Langkah 1: Buat Migration Baru (Jika ada perubahan DB) menggunakan 'php artisan make:migration'.
- Langkah 2: Naikkan Versi Aplikasi di file .env Anda:
  NATIVEPHP_APP_VERSION=1.1.0
- Langkah 3: Build Ulang Aplikasi menggunakan 'php artisan native:build'.

3. Tips Tambahan: Menjalankan Skrip Kustom Saat Update (Opsional)
Jika ingin menjalankan skrip Laravel tertentu hanya sekali tepat setelah pembaruan (misal: membersihkan cache lawas), manfaatkan Event Listener bawaan NativePHP di 'app/Providers/NativeAppServiceProvider.php' dalam fungsi 'boot()':

   use Native\Laravel\Events\App\ApplicationBooted;
   use Illuminate\Support\Facades\Event;
   use Illuminate\Support\Facades\Artisan;

   public function boot(): void {
       Event::listen(ApplicationBooted::class, function () {
           Artisan::call('cache:clear');
       });
   }

TOPIK 5: Cara Mengaktifkan Fitur Auto-Update (GitHub Releases)
================================================================================
Pertanyaan: Tolong jelaskan caranya agar bisa auto update aktif

Jawaban:
Agar fitur Auto-Update aktif dan berjalan secara otomatis saat aplikasi dibuka oleh pengguna, Anda perlu memanfaatkan fitur Updater bawaan NativePHP yang mengintegrasikan mekanisme updater milik Electron. Menggunakan GitHub Releases adalah salah satu cara termudah.

Langkah 1: Atur Konfigurasi di File '.env'
Tambahkan konfigurasi updater berikut:
   NATIVEPHP_UPDATER_ENABLED=true
   NATIVEPHP_UPDATER_PROVIDER=github
   GITHUB_OWNER=username-github-anda
   GITHUB_REPO=nama-repository-aplikasi
   GITHUB_TOKEN=ghp_xxxxxxxxxxxxxxxxxxxx
   *(GitHub Token dibuat via Settings > Developer Settings > Personal Access Tokens di GitHub).

Langkah 2: Pastikan Pengaturan di 'config/nativephp.php' Benar
Periksa file untuk memastikan pengaturan updater sudah membaca nilai dari .env:
   'updater' => [
       'enabled' => env('NATIVEPHP_UPDATER_ENABLED', true),
       'default' => env('NATIVEPHP_UPDATER_PROVIDER', 'github'),
       'providers' => [
           'github' => [
               'driver' => 'github',
               'repo' => env('GITHUB_REPO'),
               'owner' => env('GITHUB_OWNER'),
               'token' => env('GITHUB_TOKEN'),
               'vPrefixedTagName' => true,
           ],
       ]
   ]

Langkah 3: Buat Draft Release di GitHub
Ketika siap merilis versi 1.1.0:
1. Ubah versi aplikasi di .env menjadi 'NATIVEPHP_APP_VERSION=1.1.0'.
2. Buka repositori GitHub di browser, masuk ke menu Releases, dan buat Draft Release baru.
3. Berikan tag versi yang sesuai diawali huruf 'v' (contoh: v1.1.0).

Langkah 4: Publikasikan Build Menggunakan NativePHP
Gunakan perintah khusus untuk mempublikasikan:
   php artisan native:publish

NativePHP akan melakukan build otomatis dan langsung mengunggah file installer (.exe, .dmg, atau .AppImage) ke Draft Release di GitHub. Setelah selesai, klik 'Publish Release' di GitHub agar rilis bersifat publik.

Bagaimana Cara Kerjanya di Sisi Pengguna?
1. Pengguna membuka aplikasi versi 1.0.0 miliknya.
2. Di latar belakang, aplikasi mendeteksi ada versi 1.1.0 yang lebih baru di GitHub.
3. Aplikasi mengunduh file pembaruan di latar belakang tanpa mengganggu pengguna.
4. Begitu selesai, aplikasi menampilkan notifikasi/meminta restart untuk menerapkan versi baru. Saat terbuka kembali, skrip migrasi database baru langsung berjalan otomatis.
*(Catatan macOS: Memerlukan aplikasi yang ditandatangani resmi / code-signed menggunakan sertifikat Apple Developer agar fitur updater diizinkan oleh sistem).*
